## 🎫 TABLE RESERVATION SYSTEM (BRAND NEW)

### Database Schema (5 New Tables)

```
RESERVATIONS (Main)
├─ id, nightclub_id, user_id, table_id
├─ reservation_date, reservation_time
├─ guest_count, duration_hours
├─ status: pending → confirmed → active → completed/cancelled
├─ deposit_amount, total_estimated
├─ payment_status: pending → deposit_pending → deposit_received → completed
└─ special_requests, created_at, updated_at

RESERVATION_PAYMENTS
├─ id, reservation_id
├─ payment_method: direct_deposit|zelle|apple_pay|google_pay|cash_app|paypal|cash
├─ amount, status
├─ transaction_id, payment_reference_id
├─ metadata (JSON for payment provider data)
└─ completed_at

PAYMENT_METHODS (User's Saved Methods)
├─ id, user_id
├─ method_type (which payment method)
├─ is_primary (default method)
├─ metadata (tokenized account info)
└─ created_at

RESERVATION_ADDONS
├─ id, reservation_id
├─ addon_type: bottle_service|vip_upgrade|extra_hour|decorations
├─ addon_name, addon_price
├─ quantity
└─ created_at

RESERVATION_RULES
├─ nightclub_id
├─ min_party_size (default 4)
├─ max_party_size (default 20)
├─ min_deposit_percentage (default 30%)
├─ cancellation_policy_hours (default 24h)
├─ base_price_per_hour (default $100)
└─ created_at
```

### API Endpoints (Reservations)

```
GET /nightclubs/:id/reservations/availability
    Query: date, startTime, endTime, guestCount
    Returns: List of available tables

GET /nightclubs/:id/reservations/rules
    Returns: Pricing & cancellation policies

POST /nightclubs/:id/reservations
    Body: {
        tableId, reservationDate, reservationTime,
        guestCount, durationHours, specialRequests,
        addons: [{type, name, price, quantity}],
        discountCode
    }
    Returns: Reservation + pricing breakdown

GET /nightclubs/:id/reservations/user
    Returns: User's reservation history

GET /users/:userId/payment-methods
    Returns: Saved payment methods

POST /users/:userId/payment-methods
    Body: {methodType, paymentDetails}
    Returns: Payment method created

POST /reservations/:id/pay
    Body: {paymentMethod, paymentDetails}
    Handles: Direct Deposit, Zelle, Apple Pay, Google Pay, Cash App, PayPal, Cash
    Returns: Payment confirmation with transaction ID

POST /reservations/:id/cancel
    Body: {reason}
    Returns: Cancellation + refund details based on policy
```

## 🐳 DOCKER DEPLOYMENT

### Quick Start
```bash
# 1. Clone/Download project
cd easyflirt-nightclub

# 2. Configure environment
cp .env.example .env
nano .env  # Edit with your settings

# 3. Start all services
docker-compose up -d

# 4. Verify all services are healthy
docker-compose ps
curl http://localhost:3000/health
curl http://localhost:4000/health

# 5. Access the app
# Web:      http://localhost:8080
# API:      http://localhost:3000
# WebSocket: ws://localhost:4000
# Database: psql localhost:5432 -U postgres -d easyflirt_nightclub
```

### Production Deployment
```bash
# 1. Get SSL certificate
certbot certonly --standalone -d yourdomain.com

# 2. Update environment for production
nano .env
# Set:
# ENVIRONMENT=production
# API_URL=https://yourdomain.com
# WS_URL=wss://yourdomain.com

# 3. Deploy with docker-compose
docker-compose -f docker-compose.yml up -d

# 4. Monitor
docker-compose logs -f
docker stats

# 5. Backup database
docker-compose exec postgres pg_dump -U postgres easyflirt_nightclub > backup.sql
```
